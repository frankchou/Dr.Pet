# 政府開放資料 API 串接評估報告（PurePaw）

> **目的：** 評估用官方權威資料取代/補強系統中的 AI 生成內容，提升可信度並降低 AI 使用量。
> **整理日期：** 2026-06-11（依當時查證；查核檢驗端點的線上實測經 frank 指示暫停，標註於 §3C）
> **資料夾：** 原始 spec 與資料 dump 置於 `docs/govAPI_spec/`（食品/業者 JSON + `govAPI_docs/` 官方 PDF 說明書）。

---

## 一、結論摘要（先看這段）

| 官方資料 | 狀態 | 主要用途（對應本系統）| AI 減量效果 |
|---|---|---|---|
| **寵物食品資料**（產品）| ✅ 正式 API、可直接用 | 產品建檔/搜尋、營養表、成分分析 | **高**：取代 `web-search`/`extract` 生成產品資料 |
| **寵物食品業者資料** | ✅ 正式 API、可直接用 | 廠商合法性標示、推薦排序 | 中：輔助，非取代 |
| **查核及檢驗（不合格）** | ⚠️ 找到後端端點、非正式文件化 | **食安警報推播（Phase 5 核心）** | **高**：取代/補強 `news/crawl` AI 生成食安快訊 |
| **獸醫師開業執照** | ✅ 正式 API、可直接用 | SOS 急救醫院清單驗證/回填 | 中：取代人工/網搜核對 |
| **AQI 空氣品質** | ✅ 正式 API（需免費 key）| 新加值：遛狗/呼吸道提示 | —（新功能）|

**一句話：** AI 主要可從「**產品資料生成**」與「**食安快訊生成**」兩塊退場（本就該用權威資料）；AI 保留在真正需要推理/個人化的功能（診斷建議、關聯分析、月摘要、對話、換食計畫）。

## 二、可串接的官方 API（規格）

### A. 寵物食品資料（產品）— EIR634 ✅
- **端點**：`https://data.moa.gov.tw/Service/OpenData/TransService.aspx?UnitId=wxV177kLhEE3`
- **方法/格式**：GET → JSON；單次最多 1000 筆；**更新頻率「即時」**；提供單位：農業部動物保護司。
- **進階查詢**：`&$top={n}&$skip={n}&欄位=值`（多參數用 `&` 串、中文需 URLEncode）。例：`&fitem=零食&fsource=輸入`。
- **欄位**：`ID`食品序號、`fname`名稱、`fitem`種類、`fsource`來源、`fwcn`規格、`fmat`主要原料及添加物、`fnut`主要營養成分及含量、`fusage1`適用寵物、`fusage2`使用方法、`fusage3`保存方法、`forigin`原產地、`flegalname`廠商。
- **授權**：數位發展部授權條款（≈政府開放資料，**可商用**，須標示來源）。
- **本地 dump**：`寵物食品資料.json`（9999 筆）、`寵物食品資料進階搜尋.json`。
- ⚠️ **注意**：`fmat`、`fnut` 是 **tab/換行串接的非結構化字串**（如 `粗蛋白(至少)130%...`，且部分數值含格式雜訊如「130%」實為 13.0%）→ app 端要寫 parser，**不能直接當數字用**。

### B. 寵物食品業者資料 — EIR633 ✅
- **端點**：同平台 `TransService.aspx?UnitId=<業者UnitId>`（見 `govAPI_docs/...EIR633...pdf`）。
- **欄位**（實際 dump）：`ID`、`legaltype`業者類別、`legalname`業者名稱、`ownname`負責人、`legaltel`電話、`legaladdress`地址、`contactname`聯絡人、`legalcountry`縣市、`legalgzone`區。
- **本地 dump**：`寵物食品業者資料.json`（8226 筆）、`寵物食品業者資料進階搜尋.json`。

### C. 查核及檢驗專區（不合格/檢驗/查核）— ⚠️ 找到後端端點、非官方文件化
> petfood.moa.gov.tw/Web/Audit 是 Vue 3 SPA，三個分頁各打一支 `.ashx` 後端 handler（POST JSON，**無需登入/token/CSRF**）。**這不是「文件化的 OpenData API」**，是逆向其前端找到的內部端點，農業部未保證穩定性（曾從 coa.gov.tw 換 moa.gov.tw）。
> **以下對應與細節以 frank 瀏覽器實測為準**（見 `govAPI_docs/檢驗及查核專區抓資料的方法.txt`），先前研究員初查的 handler 對應有誤，已更正。
- **共通**：`POST https://petfood.moa.gov.tw/Handler/Web/<X>Handler.ashx`，headers **`Content-Type: application/json` + `X-Requested-With: XMLHttpRequest`（兩個缺一不可，少了回「傳輸的資料為空」）**；回傳 `{Success, Message, RowCount, totalSize}`，**`Message` 是 JSON 字串、要再 `JSON.parse` 一次**才是資料陣列。

| 分頁 | Handler | Method / action | 查詢參數 | 資料量/翻頁 |
|---|---|---|---|---|
| 檢驗**不合格**產品 | `FailedInspectionHandler.ashx` | `FailedInspectionData` / `getFailedInspectionFood` | 日期區間 `PostSDate`/`PostEDate`、currentPage、pageSize、orderByColumn:PostDate、sortDirection:desc、K_Delete:"0"、County、KeyWord | 約 **41 筆**（2015 起）；**RowCount 不可靠**，以實際筆數 < pageSize 判斷結束 |
| 檢驗結果 | `InspectionHandler.ashx` | `InspectionData` / `getInspectionData` | 年月區間 Year/Month/EYear/EMonth、County、KeyWord、分頁、dataType:0 | 約 **4,860 筆**；總數在每筆的 `TotalCount` 欄位 |
| 查核結果 | `ExamineHandler.ashx` | `ExamineData` / `getExamineData` | 年月區間 Year/Month/EYear/EMonth、CountyName、KeyWord、分頁、dataType:0 | 回**巢狀物件**：`_ExamList`(清單,含 TotalCount) + `_ExamResultList`(逐項明細,用 Year+Month+ESort 關聯) + `_ExamStatus` |

- **欄位**：County、GovName(發布機關)、CompanyName、FoodName、MFDate(製造日)、EXPDate(有效日)、InspectionMethod、ReasonAndAmount(不合格原因與數量)、DisposalSituation(處置)、PostDate(發布日)；不合格列另含 `FileBase64string` 內嵌縮圖(**極大，9 筆≈10MB，務必丟棄或另存**)。`EXPDate:"1900/01/01"` 代表無效期。
- **狀態**：✅ **已用 `petfood_scraper.py` 實跑抓取成功**（2026-06-11，輸出於 `govAPI_audit_data/`）：不合格 **41**、檢驗 **4,860**、查核清單 **1,232**、查核明細 **9,209** 筆。不合格最新發布日 **2026/05/21**（資料新、官方持續更新 → **食安警報來源可用**）。腳本三個 `fetch_*` 函式可直接重用接 DB。
- **代碼欄位**：`County`/`Suitable`/`ItemType` 為代碼（需建對照表）；`GovName`/`CompanyName`/`FoodName`/`ReasonAndAmount`/`DisposalSituation`/`PostDate` 為純文字（食安警報所需欄位足夠）。
- ⚠️ 此為唯一可程式化取得「檢驗/查核」的途徑（無對應 OpenData 資料集）；建議**每日低頻排程 + 錯誤告警**。

## 三、對應到本系統的強化點 + AI 減量（核心）

### 1. 產品建檔／搜尋 → 用「寵物食品資料 API」取代 AI 生成
- **現況**：`AddItemModal` 透過 `/api/products/web-search`（AI 生成產品名/成分/營養）；標籤辨識用 `/api/extract`（AI vision）。AI 生成可能不準、耗 token。
- **改法**：先查官方「寵物食品資料」（依 `fname`/`flegalname` 比對）→ 命中就用官方 `fmat`/`fnut`/`fitem`/`fusage1`/`forigin`/`flegalname` 建檔；查無再退回 AI。
- **效益**：**大幅減少 web-search/extract 的 AI 呼叫**；產品成分/營養來自官方登記，權威可信。
- **連帶強化**：飲食頁**營養表**可用官方 `fnut`（解析後）取代/校正 AI 估算；**成分分析** `/api/analysis` 規則引擎比對更可靠。

### 2. 食安警報推播（Phase 5）→ 用「查核不合格」取代/補強 AI 快訊 ★frank 最重視
- **現況**：`/api/news/crawl` 由 AI 生成食安警報快訊（來源非官方、可信度有限）。
- **改法**：以官方「檢驗不合格產品」清單為**真實警報來源**；定期拉取 → 比對使用者 `PetProduct` 的廠商/品名 → 命中即**個人化頭條推播**（沿用 Phase 5 既有 highlight 機制）。
- **效益**：**食安警報變權威即時**、取代 AI 生成新聞、省 AI；正中「主動推播食安警報」的產品定位。
- ⚠️ **前置**：須先解決 §3C 的端點正式機/穩定性問題（見風險）。

### 3. 廠商合法性 → 用「業者資料 / 特定寵物業」標示與排序
- 產品卡、推薦結果可標「✅ 官方登記業者」；`/api/recommend` 可優先官方登記產品（可信度加分）。

### 4. SOS 急救醫院清單 → 用「獸醫師開業執照」驗證/回填
- 現況清單靠網搜+frank 人工核對（含多筆 🟡 待確認電話/地址）。可用官方全國名冊**自動驗證地址/電話、補齊涵蓋**，減少人工。

### 5. （新加值）AQI → 健康提示
- 依使用者縣市顯示空品，給「今日是否適合外出/呼吸道敏感毛孩注意」。非取代 AI，是新功能。

## 四、風險與注意事項

1. **查核檢驗非正式 API**：`.ashx` 是逆向所得的內部端點，農業部未文件化、不保證穩定；且測到的是「測試機」、未取得真實資料。**正式上線前必須**：確認正式機網址、打通不合格那支取得真實資料、評估農業部是否可能改版/封鎖；或改走「年度 PDF/網頁定期人工核對」備援。建議去函 `opendata@moa.gov.tw` 詢問是否能開放正式檢驗 API。
2. **非結構化欄位**：`fmat`/`fnut` 為字串、含格式雜訊（如「130%」=13.0%），需 parser + 容錯，不可直接數值化。
3. **資料涵蓋限制**：官方「寵物食品資料」僅含**有在台登記**的產品；水貨/未登記/境外電商產品查無 → 仍需 AI 退場機制（fallback）。
4. **授權標示**：政府開放資料須**標示來源**（提供機關+資料集名稱），否則授權自始無效 → UI/關於頁要加註。
5. **同步策略**：產品/業者資料量大（各約 8k–10k+）、更新「即時」→ 建議**定期排程同步進我們 DB**（非每次即時打），食安不合格則較高頻輪詢。
6. **API key 與流量**：data.moa 非會員只能取第 1 頁，**完整翻頁需申請 api_key**；AQI 需免費 key。每日次數上限未查證，申請時確認。
