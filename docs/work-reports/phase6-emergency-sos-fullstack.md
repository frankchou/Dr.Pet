## 2. UI 升級（EmergencyCareModal）

### 四組分類篩選（文字搜尋前面）
順序：寵物種類 → 地區 → 症狀科別 → 特殊資源/設備，皆為可多選 chips。
- 邏輯：**組內 OR、組間 AND**，再疊上文字模糊搜尋（搜名稱/地區/行政區/地址）。篩選 + 文字同時生效。
- 各組只列「資料中實際存在」的值：用 `collectOptions()` 掃描清單收集出現過的值，再依固定排序 `orderedOptions()` 過濾，避免列出空選項（例如地區僅出現有醫院的 4 縣市）。
- 有選取時顯示「清除篩選（n）」。

### 卡片
- 顯示營業時間（hours）；缺則隱藏該行，「待確認」文字照顯示。
- 地址組合 region + district + 街道顯示。
- 科別與資源以小標籤呈現。

### 電話可點擊撥號 + 確認
點電話 → 跳自製 styled 確認對話框（顯示「撥打 {phone} 給「{醫院名}」？」），確認後才 `window.location.href = 'tel:...'`（撥號前去除非數字符號）。取消或點背景關閉。行動裝置撥號、桌機不報錯。

### 核實提示
`verified === 'medium'` 或 hours 含「待確認」者，卡片加暖色提示「資料未完全核實，建議致電前再確認」。

### 其他
維持 bottom-sheet 樣式與品牌色；空篩選結果顯示空狀態。靜態清單，所有帳號（含 demo）顯示相同，無 demo 分流。

## 3. 手機排版優化（追加：四組篩選後 frank 反映搜尋條件變多、手機要顧排版）

### 問題
原本每組篩選用 `flex flex-wrap`，選項多（尤其「症狀科別」14 項）時會折成多列，
垂直高度不可預期，手機上把篩選區撐高、清單被擠掉。

### 做法：每組 = 一條「橫向可滑動」chip 列（刻意不收合）
急救畫面講求快速，**不把篩選藏進收合面板**（緊急時多一次點擊不利）。
改成緊湊、常駐設計：
- `FilterGroup` 重構為「左標籤 + 右橫滑列」：
  - 左側常駐小組名（縮短為「種類 / 地區 / 科別 / 設備」），`shrink-0 w-9` 固定寬度對齊。
  - 右側 chips 列：`flex flex-nowrap overflow-x-auto whitespace-nowrap hide-scrollbar`，
    一排不換行、可左右滑；沿用 globals.css 既有的 `.hide-scrollbar`（隱藏捲軸但保留捲動）。
  - 用 `-my-1 py-1` 補回滑動列的縱向內距，避免 chip 焦點環被裁切。
- 四組固定排成四條細列，**垂直高度可預期**，不再因選項多而把清單擠掉。
- 篩選區整塊（標題列 + 四條 chip 列 + 文字搜尋）`shrink-0` 置頂；
  清單區維持 `flex-1 min-h-0 overflow-y-auto` 吃剩餘高度，bottom-sheet 仍 `max-h-[90dvh]`。

### chip 狀態與品牌色
- 選中：品牌色 `#C4714A` 實心白字；未選：白底 `border-slate-200` 細框。
  （原誤用急救紅 `#C0392B`，此次校正為品牌主色；急救紅僅保留給 SOS icon / 撥號鈕等強提示。）
- chip `px-3 py-1.5 text-xs`，觸控高度約 30px，緊湊但好點按。

### 清除全部
篩選區頂端一條「快速篩選」標題列，右側在有作用中篩選時顯示
「清除全部（n）」小按鈕（品牌色、含 active 數量），位置固定不隨清單捲動。

### 文字搜尋
維持在四條篩選列下方、清單上方；輸入框 padding 由 `py-3` 收為 `py-2.5` 讓整塊更緊湊。

### 高度估算（手機）
四條 chip 列每條約 30px chip + gap，單列高約 38px → 四列約 152px；
加上「快速篩選」標題列（約 20px）與文字搜尋框（約 42px）與區塊 padding，
整個置頂篩選區約 **260～280px 高、且為固定值**（不再隨選項數膨脹），
其餘高度全留給清單捲動區。

### 桌機相容
容器仍在 `max-w-[480px]` 內；橫向滑動列在桌機可正常顯示與滑動（含滑鼠拖曳/觸控板）。

### 未動壞既有功能
僅調版面/樣式/捲動，未改篩選邏輯（組內 OR、組間 AND + 文字）與資料；
撥號確認、營業時間、核實提示、空狀態維持原行為。

## 4. 地址可點擊開地圖（追加：frank 要求使用者自己決定要不要導航）

### 需求
卡片地址原為純文字 + PinIcon。改成可點擊 → 開 Google Maps 並帶入該地址，
讓使用者抵達地圖 App 後自行決定是否導航（刻意不直接給導航路線）。

### 做法
- 新增 `openMap(address)`：用 Google Maps **search 模式**（顯示在地圖上，非導航）：
  `https://www.google.com/maps/search/?api=1&query=${encodeURIComponent(address)}`，
  以 `window.open(url, '_blank', 'noopener')` 開新分頁。
- `fullAddress` 已組出「region（縣市）+ district（行政區）+ address（街道）」完整地址，
  直接沿用同一字串傳給 `openMap`，**與卡片顯示的完整地址一致**（不另組）。
- 地址改為 `<button>`，點擊直接開地圖、**不做二次確認**（開地圖為低風險動作）；
  電話的「撥號確認」流程完全不動。
- `address` 為空（如「會思考的狗」無固定據點）時維持原樣，不渲染可點地址。

### 視覺區分電話 / 地址
- 電話：維持急救紅 `#C0392B`（強提示，且需撥號確認）。
- 地址：改用品牌色 `#C4714A`，文字加底線（`decoration-[#C4714A]/40`），
  PinIcon 後加一個外連小箭頭 `ExternalArrowIcon`（暗示跳轉外部地圖）。
- 兩者皆為 `flex items-center gap-2` 的按鈕、`hover:underline`，可點樣式風格一致但顏色區隔；
  按鈕本身即足夠觸控區（整行可點）。

### 未動壞既有功能
資料、四組篩選、撥號確認、營業時間、核實提示、空狀態皆未更動。
