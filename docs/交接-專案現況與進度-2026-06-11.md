## 2. 重要工作慣例（新成員必讀）
1. **commit 由 frank 自己執行**：Claude 只「備好指令」給 frank，不自行 commit；**dev.db 一律排除**（`git add -A && git reset dev.db`）。
2. **四份文件鐵則**：每個有意義的改動要更新 `系統架構 / 系統機制 / 版本紀錄 / 待辦清單`，角色出 work-report（`docs/work-reports/`）。勾選用 `[V]` 不用 `[x]`。
3. **版本紀錄 hash 回填**：commit 後把短 hash 填回對應條目的「Git 紀錄」。
4. **demo 分流**：demo 帳號**所有操作跟一般一樣（走真實測試 DB dev.db）**，差別只在「**看到的 AI 內容是 mock**」（各 AI 端點以 `isDemoUser` gating）。錯誤回報/問題回報/評論等「非 AI 動作」demo 也真的寫 DB+寄信，只用信件標題 `[測試]`/`[正式]` 區分環境。**正式站要關掉 demo 登入口**（Vercel 不設 `DEMO_ENABLED`/`NEXT_PUBLIC_DEMO_ENABLED`）。
5. **按圖施工**：待辦標「設計圖：docs/features/ui-mockups/xxx.jpg」的項目，實作前務必開圖、以圖為準。
6. **不擅自延後 review 發現**：review 出來的項目要讓 frank 定奪範圍，不自行 defer。
7. **安全資料不捏造**：急救清單、官方資料等攸關安全者，查不到就留空標「待確認」，**絕不編造**。

## 4. ▶ 進行中：政府開放資料 API 串接評估（尚未動程式）
**目標**：用官方權威資料取代/補強系統 AI 生成，降 AI 用量、提升可信度。

**已產出文件**（都在 `docs/govAPI_spec/`）：
- `串接評估報告.md` ★ **主報告**：可串接 API 清單 + **對應系統強化點 + AI 減量**（核心）+ 風險 + 實作優先序。
- `govAPI_docs/`：農業部官方 PDF 說明書（EIR633 業者、EIR634 食品）+ `檢驗及查核專區抓資料的方法.txt`（frank 瀏覽器實測的逆向成果）。
- `govAPI_audit_script/petfood_scraper.py`：查核/檢驗三支 `.ashx` 的抓取腳本（可重用接 DB）。
- 資料 dump：`寵物食品資料.json`(9999)、`寵物食品業者資料.json`(8226) 及進階搜尋版。

**結論重點**：
- ✅ **寵物食品資料/業者資料**＝正式 OpenData API（`data.moa.gov.tw/Service/OpenData/TransService.aspx?UnitId=...`），即時更新、可商用 → 用於**產品建檔/搜尋/營養表**，取代 `web-search`/`extract` 的 AI。
- ⚠️ **查核及檢驗（不合格）**＝無官方 API，但 `petfood.moa.gov.tw/Handler/Web/*.ashx` 三支可呼叫（POST JSON，兩個 header 必帶，`Message` 要二次 parse）→ 用於 **Phase 5 食安警報的真實來源**（取代 AI 生成快訊）。frank 最重視這塊。
- ✅ **獸醫師開業執照** API → 驗證/回填 SOS 醫院清單。

**目前卡點 / 下一步（接手者從這裡繼續）**：
1. **抓取查核檢驗實資料**：用 `petfood_scraper.py` 跑（`pip install requests pandas openpyxl; python petfood_scraper.py --out govAPI_audit_data --no-images`）。**此步驟 frank 已暫停 Codespace 內執行**，待恢復；需網路（POST petfood.moa.gov.tw）。
2. 申請 api_key：`data.moa`（翻頁完整資料）、`data.moenv`（AQI，若做）。
3. 確認後開 **Phase 7「官方資料介接」** 派工：先做產品資料同步（P1）→ 食安不合格警報（P1，frank 最重視）→ SOS 醫院驗證（P2）。
4. 注意：`fmat`/`fnut` 非結構化字串需 parser；官方僅含在台登記產品，未登記者仍需 AI fallback；UI 要標示資料來源（授權要求）。
