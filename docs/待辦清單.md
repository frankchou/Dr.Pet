## Phase 1 — 共同飼主 Email 邀請流程（當期主任務，P1）

### 1-A 前置：Gmail API 憑證 ⚠️【frank 要做的事，阻擋 1-B】
> 這是寄信功能的前置條件，沒完成 1-B 無法運作。以下由 frank 操作，Claude 提供逐步畫面指引。

**步驟（在 Google Cloud Console 操作）**
- [ ] 進 Google Cloud Console，選到「登入功能在用的那個既有專案」
- [ ] APIs & Services → Library → 搜尋 **Gmail API** → 按 **Enable** 啟用
- [ ] OAuth consent screen：確認可用；在 Scopes 加入寄信權限 `https://www.googleapis.com/auth/gmail.send`
- [ ] 若寄件帳號非測試名單內，於 consent screen 的 Test users 加入該寄件 Gmail（或把 app 設為 Production）
- [ ] Credentials → 沿用或新建一個 **OAuth 2.0 Client ID（Web application）**，記下 Client ID 與 Client Secret

**取得 refresh token（用 OAuth Playground 最快）**
- [ ] 開 https://developers.google.com/oauthplayground →右上齒輪勾「Use your own OAuth credentials」，填入上面的 Client ID / Secret
- [ ] （需先在該 OAuth Client 的 Authorized redirect URIs 加入 `https://developers.google.com/oauthplayground`）
- [ ] 左側 Scopes 輸入 `https://www.googleapis.com/auth/gmail.send` → Authorize → 用**寄件 Gmail 帳號**登入同意
- [ ] Exchange authorization code for tokens → 複製產生的 **Refresh token**

**📦 frank 要提供給 Claude 的 4 樣東西（放進環境變數）**
- [ ] `GMAIL_CLIENT_ID` — OAuth Client ID
- [ ] `GMAIL_CLIENT_SECRET` — OAuth Client Secret
- [ ] `GMAIL_REFRESH_TOKEN` — 上一步取得的 refresh token
- [ ] `GMAIL_SENDER` — 寄件人 email（即授權同意的那個 Gmail）

**環境變數設定位置**
- [ ] 本機 `.env`（供 `npm run dev` 測試）
- [ ] Vercel 專案 → Settings → Environment Variables（供正式站）
- [ ] 同時確認 `NEXTAUTH_URL` 在正式站指向 Vercel 網域（邀請信連結會用到，不能是 localhost）

> 🔐 安全提醒：refresh token 等同寄信權限，勿提交進 git、勿貼上公開頻道，只放環境變數。
