## 產品概覽

**PurePaw 無敏毛孩** 是專為台灣飼主打造的 AI 寵物營養健康管理平台，核心功能為即時掃描寵物食品成分、AI 個人化飲食建議、健康日誌追蹤。前身品牌為「寵物隨行醫師 Dr. Pet」，v2.0.0 起全面更名。

## 版面架構（RWD）

```
root layout (src/app/layout.tsx)
├── ClientShell          ← 身份驗證 + 免責聲明守衛
│   ├── Sidebar          ← 桌面左側欄（md 以上顯示，w-64 fixed）
│   └── main content area
│       ├── {page children}
│       └── BottomNav    ← 手機底部導覽列（md 以下顯示）

/landing（獨立 layout，不套用 App shell）
└── landing/layout.tsx   ← 覆蓋父層 layout，僅回傳 children，無 Sidebar/BottomNav/ClientShell
```

Landing page 使用 `src/app/landing/layout.tsx` 覆蓋父層 layout，完全跳過 `ClientShell`、`Sidebar`、`BottomNav`，適合對外公開的行銷頁面。

**手機（< md）**：底部導覽列 `BottomNav`，高度 60px，含 4 個分頁 tab + 中央凸起相機 FAB。導覽固定 5 項，順序為 **毛孩(`/`)｜飲食(`/diet`)｜照相(`/scan`，中央 FAB)｜日誌(`/diary`)｜快訊(`/news`)**。Active tab 以 `bg-[#111111] text-white rounded-2xl` 圓角黑底 icon 指示器呈現。頂部 sticky header 左上角顯示使用者頭像（手機限定，`AppShell` 內），點擊開啟 ProfileMenu（切換毛孩 / 設定 / 登出），對齊桌面 Sidebar 的使用者選單；右上角鈴鐺按鈕導向 `/news`。
**桌面（>= md）**：左側欄 `Sidebar`，寬 256px fixed；主內容區 `ml-64` 偏移。桌面 header 左側改顯示頁面標題與副標題。導覽與手機一致，順序為 **毛孩｜飲食｜照相｜日誌｜快訊**。

**導覽隱藏項**：「營養分析(`/nutrition`)」與「AI 諮詢(`/nutritionist`)」兩個入口已自 Sidebar 與 BottomNav 移除（`NAV_ITEMS` / `RIGHT_NAV_ITEMS` 內加註說明），**頁面與路由皆保留**，日後把項目加回 nav 即可恢復。

**Viewport 設定**：`src/app/layout.tsx` 匯出 `export const viewport = { viewportFit: 'cover' }`，讓 `env(safe-area-inset-*)` 在手機上大於 0，配合 bottom-sheet modal 底部安全區 padding 真正生效（home indicator 不擋住按鈕）。

**AI 諮詢頁（`/nutritionist`）例外 layout**：`AppShell` 偵測 `isChat = pathname === '/nutritionist'`，對 `<main>` 切換 `overflow-hidden`（停用頁面 scroll），不渲染 sticky header，content wrapper 改為 `h-full`。頁面內部分三 flex 區：頂部 `shrink-0`（標題 + 免責聲明 + 寵物切換）、中間 `flex-1 min-h-0 overflow-y-auto`（唯一 scroll 區）、底部 `shrink-0`（輸入列）。

## API Endpoints

> **AI/外部端點依帳號分流總則**：所有會呼叫 Anthropic 或外部搜尋的端點，一律「先 `auth()` + 既有權限檢查 → 再判 `isDemoUser(session)`」；**demo 帳號（`demo-user` / `demo@drpet.com`）→ 回固定 mock（不打 AI、不打外部搜尋）；測試帳號與真實環境帳號 → 走真實 AI / 外部搜尋**。mock 結構嚴格符合各端點既有回傳型別，前端不需改。涵蓋 15 支（analyze、chat、diary-parse、diet-analysis、extract、instant-analyze、month-summary、nutrition-ai、products/lookup、products/web-search、recommend、switch-plan-ai、symptoms/advice、tasks、news GET）；`news/crawl`（排程生成、非帳號觸發）**不分流**，維持真 AI。詳見系統機制「demo 帳號全 mock 分流機制」。

| 路徑 | 方法 | 功能 |
|------|------|------|
| `/api/extract` | POST | 視覺 AI 擷取食品標籤成分 |
| `/api/instant-analyze` | POST | 照片 → 成分安全判讀（safe/caution/danger），存 `InstantAnalysis` |
| `/api/chat` | POST | AI 對話，注入寵物背景資料為 system prompt |
| `/api/analyze` | GET / POST | GET：依 `?petId=` 取該寵物最新一筆 `AIInsight`（關聯分析顯示端）；POST：跑相關性分析並存 `AIInsight` |
| `/api/nutrition-ai` | POST | AI 營養摘要（產品堆疊） |
| `/api/recommend` | POST | AI 產品推薦 |
| `/api/tasks` | POST | 生成每週照護任務清單 |
| `/api/analysis` | GET | 規則式成分知識庫分析（不呼叫 AI） |
| `/api/news/crawl` | GET / POST | AI 生成寵物食安/危險禁忌/健康知識三類快訊並寫入 `NewsArticle`。GET 供 Vercel Cron 每日觸發、POST 供手動觸發，兩者皆以 `Authorization: Bearer <CRON_SECRET>` 授權；prompt 附 `VET_REFERENCE_SCOPE`，近 7 天「同分類同標題」去重。**全站公開、非 pet-scoped** |
| `/api/symptoms/advice` | GET | 依該毛孩、該症狀類型近 30 筆紀錄生成 AI「可能原因／建議做法」（pet-scoped，`requirePetAccess` 先擋再呼叫 AI）。結果快取於 `AIInsight`；`?refresh=1` 強制重生。無紀錄回 `{ advice: null }` 不打 AI |
| `/api/month-summary` | GET | 依 `?petId=&yearMonth=YYYY-MM` 後端聚合當月 `DailyHealthLog`，再請 AI 生白話健康解讀摘要（pet-scoped，`requirePetAccess` 先擋）。程序內 Map 快取（上限 200、近 LRU 淘汰、依 statsHash 命中）；無資料回 `{ summary: null }` |
| `/api/switch-plan-ai` | POST | 依 `{ petId, dayCount }` 取該毛孩近 7 日日誌生成換食「比例排程／身體特徵監控／晉升淘汰建議」（pet-scoped，`requirePetAccess` 先擋）。含 AI 數值驗證與降級；近 7 日日誌 < 3 天直接走降級不打 AI |
| `/api/products/web-search` | POST | （既有）AI + web_search 搜尋真實寵物食品。**Phase 4 新增 `detailed` 模式**：AI 一併抓回成分／營養添加物／營養成分表／商品規格／製造代理／每日餵食量／驗證標章／數據出處，並依該毛孩健康狀態判定風險樣式（`risk.style = none/product/brand`） |
| `/api/pets` | CRUD | 寵物資料。GET 改以 `OR: [{ userId }, { members.some.userId }]` 查詢，讓共同飼主也看得到被分享的毛孩；POST 建立毛孩時一併建立 owner membership。約 30 支寵物資料 API 已加上權限檢查（讀寫允許 owner/co_owner；刪毛孩、邀請管理 owner-only）|
| `/api/symptoms` | CRUD | 症狀記錄（含 grooming / medication type）|
| `/api/pet-products` | CRUD | 寵物產品清單 |
| `/api/reactions` | CRUD | 每日產品反應評分 |
| `/api/health-metrics` | GET/POST | 每日健康指標（BCS/活力/水分）|
| `/api/diary-records` | GET | 依日期查詢該天所有紀錄（症狀+使用+健康指標）|
| `/api/diary-dates` | GET | 依 `?petId=&yearMonth=YYYY-MM` 聚合 7 種紀錄來源，回傳當月「有任何紀錄」的不重複日期清單（供月曆/週曆圓點與「已紀錄天數」共用）|
| `/api/diary-parse` | POST/PUT | AI 解析隨記文字 → 結構化紀錄 → 確認後儲存 |
| `/api/daily-health-log` | GET/POST | 每日健康日誌（upsert，含 13 個身體部位欄位）|
| `/api/medication-record` | GET/POST | 用藥看診紀錄（GET 支援 `?recent=N`）|
| `/api/grooming-record` | GET/POST | 洗澡美容紀錄（GET 支援 `?date=` 與 `?recent=N` 兩種模式）|
| `/api/measurement-record` | GET/POST | 量測追蹤紀錄（體重/BCS/血糖/血壓/體溫）|

## 認證方式

**現況**：已串接 NextAuth Google OAuth（`signIn('google')`）。`session.user.id` 作為真實用戶識別，登入後由 `ClientShell` 同步寫入以下 localStorage 項目：

| localStorage key | 值 | 說明 |
|---|---|---|
| `drpet_userId` | 字串 | 用戶 ID（由 NextAuth session 同步寫入） |
| `drpet_nickname` | 字串 | 顯示名稱 |
| `purepaw_disclaimer_ack_v1_${userId}` | `'1'` | 使用者已閱讀並同意免責聲明（**by-user 隔離**：不同帳號各自獨立儲存，換帳號需重新同意） |
| `drpet_currentPetId` | 字串 | 目前選取的寵物 ID |
| `purepaw_record_params` | JSON 字串 | 紀錄參數設定（10 個 RecordParam 項目的啟用狀態） |
| `purepaw_daily_tasks` | JSON 字串 | 每日任務「定義」清單（`{ key, label, icon, enabled, note }[]`，由 `useDailyTasks` 管理） |

開發測試帳號（`NEXT_PUBLIC_DEMO_ENABLED=true` 時顯示）可用 email/password 登入，透過 NextAuth Credentials Provider 驗證。

## 資料庫架構重點

- `Pet` 為核心實體，幾乎所有模型均以 Pet delete 為級聯刪除對象。
- 陣列型欄位（如 `mainProblems`、`allergies`、`photos`）儲存為 JSON 字串，讀取須用 `parseJson()`（位於 `src/lib/utils.ts`）。
- `PetProduct` 管理寵物的固定／試用產品清單（`listType: "fixed" | "trial"`）。
- `ProductReaction` 記錄每日產品反應評分，唯一約束 `@@unique([petId, productId, date])`。
- `HealthMetric` 記錄每日健康指標（BCS 體態評分 1–9、活力 low/medium/high、水分 low/medium/high），唯一約束 `@@unique([petId, date])`。
- `DailyHealthLog` 記錄每日完整健康狀態日誌（食慾/飲水/排便/泌尿/活力/情緒/皮毛/眼耳/牙齒/消化/呼吸/神經/生殖），唯一約束 `@@unique([petId, date])`；多選欄位以 JSON array string 儲存。
- `MedicationRecord` 記錄用藥與看診事件（疫苗/驅蟲/處方/看診備注均為 JSON array），支援照片與下次提醒日期。
- `GroomingRecord` 記錄洗澡美容事件，分自洗/外送兩種模式，四個進階療程各有獨立欄位，支援照片與下次提醒日期。
- `MeasurementRecord` 記錄量測追蹤數值（體重/BCS/RRR/血糖/血壓/體溫）。
- `NewsArticle` 記錄健康快訊（分類 food_safety / danger / health、是否緊急、來源連結），由 `/api/news/crawl` 的 AI 生成寫入。
- `AIInsight` 除原本的關聯分析用途外，**Phase 4 起亦兼作「症狀詳情頁 AI 建議」的快取表**：每筆建議存成一列，`symptomType` 為該症狀類型、`rationale` 存「可能原因」、`recommendedActions` 存建議陣列，並把「依紀錄算出的 sha1 dataHash」塞進本功能未使用的 `suspectedTriggers` 欄位（格式 `["__hash__:<hash>"]`）作為快取鍵；沒新紀錄時 hash 不變即回快取，不重打 AI。
- `DailyMealPlan` 為單日配餐計畫（`@@unique([petId, date])`），底下掛多筆 `MealPlanItem`（早/午/晚餐項目，可關聯 `Product` 或自填品名、份量、估重、標籤）。
- `NewsArticle`、`DailyMealPlan`、`MealPlanItem` 三個 model 早已存在於 migration、實際 DB 與程式碼中，但 `schema.prisma` 一度缺漏；現已補回，使 schema 與資料庫一致。
- Prisma v7 的 `DATABASE_URL` 不放在 `schema.prisma`，改由 `prisma.config.ts` 設定，runtime 於 `src/lib/prisma.ts` 建立帶 libsql adapter 的 `PrismaClient`。

### Vercel Cron 排程設定（`vercel.json`）

快訊 AI 生成由 Vercel Cron 每日觸發，設定於 `vercel.json`：

```json
{ "crons": [ { "path": "/api/news/crawl", "schedule": "0 2 * * *" } ] }
```

每日 02:00 UTC（台灣 10:00）由 Vercel Cron 以 **GET** 觸發 `/api/news/crawl`，正式站由 Vercel 自動帶 `Authorization: Bearer $CRON_SECRET`。Vercel Hobby 方案 cron 上限為每日一次，目前設定符合限制。`CRON_SECRET` 需於 Vercel → Settings → Environment Variables 設定，否則授權一律失敗。

### `.env` 與 `.env.local` 的分工（本機開發 vs 正式環境）

| 檔案 | 用途 | 誰會讀 |
|------|------|--------|
| `.env` | 保留**正式環境**的設定（`DATABASE_URL` 指向正式 Turso 資料庫） | Vercel 正式機、未明確覆蓋時的本機 |
| `.env.local` | **本機開發覆蓋檔**，把 `DATABASE_URL` 指回本機 `dev.db` | 僅本機（Next.js 載入順序中 `.env.local` 優先於 `.env`；**Vercel 不讀此檔**） |

因此本機開發時自動連 `dev.db`（內含 seed 灌入的 demo 資料 + 最新 migration），不會誤動正式庫；正式機因為讀不到 `.env.local`，仍用 `.env` 的 Turso。demo 帳號、Google 登入帳號、正式使用者三者的資料**靠「同一個資料庫內的資料歸屬（userId）」區隔**，並非多個資料庫。
