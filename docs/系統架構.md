# 系統架構

> 最後更新：2026-06-02（v1.4.0 UI/功能修復批次）

---

## 產品概覽

**PurePaw 無敏毛孩** 是專為台灣飼主打造的 AI 寵物營養健康管理平台，核心功能為即時掃描寵物食品成分、AI 個人化飲食建議、健康日誌追蹤。前身品牌為「寵物隨行醫師 Dr. Pet」，v2.0.0 起全面更名。

## 技術棧

| 層級 | 技術 | 版本 / 備注 |
|------|------|------------|

| 字體 | Quicksand（英數）+ Noto Sans TC（中文） | 由 Google Fonts CDN 載入 |

## 版面架構（RWD）

```
root layout (src/app/layout.tsx)
├── ClientShell          ← 身份驗證 + 免責聲明守衛
│   ├── Sidebar          ← 桌面左側欄（md 以上顯示，w-64 fixed）
│   └── main content area
│       ├── {page children}
│       └── BottomNav    ← 手機底部導覽列（md 以下顯示）

/landing（獨立 layout，不套用 App shell）
└── landing/layout.tsx   ← 覆蓋父層 layout，僅回傳 children，無 Sidebar/BottomNav/ClientShell
```

Landing page 使用 `src/app/landing/layout.tsx` 覆蓋父層 layout，完全跳過 `ClientShell`、`Sidebar`、`BottomNav`，適合對外公開的行銷頁面。

**手機（< md）**：底部導覽列 `BottomNav`，高度 60px，含 4 個分頁 tab + 中央凸起相機 FAB。  
**桌面（>= md）**：左側欄 `Sidebar`，寬 256px fixed；主內容區 `ml-64` 偏移。

## 路由結構

| 路徑 | 頁面 | 說明 |
|------|------|------|
| `/` | 首頁 Dashboard | Pet Hero 卡片、健康檔案概覽、快速功能、重要日程、健康指標、營養綜合分析 |
| `/diary` | 日誌 | 月/週曆、AI 隨記、用藥看診、洗澡美容、日常飲食紀錄、使用中產品、換食計畫 |
| `/scan` | 即時成分掃描分析 | 三階段 Modal（capture→analyzing→result）+ 歷史記錄列表 |
| `/nutritionist` | AI 營養師對話 | AI 對話、建議題、觀察計畫、多寵物切換 |
| `/news` | 快訊 | 靜態示範內容（品牌相關 + 一般通知） |
| `/landing` | 行銷落地頁 | Hero/Marquee/Stats/About/Features/How it works/FAQ/CTA/Footer；獨立 layout |
| `/settings` | 設定頁 | 毛孩檔案（滑動卡片 + CRUD）+ 紀錄參數設定（13 toggle） |
| `/pet`, `/pet/new`, `/pet/[id]` | 寵物檔案管理 | 寵物基本資料 CRUD |
| `/analysis` | 成分知識庫分析 | 規則式成分分析（不呼叫 AI） |

### v1 路由重新導向（永久 301）

`next.config.ts` 設定 7 條永久重新導向，確保 v1（Dr. Pet）時期的舊網址不會 404：

| 舊路由（v1） | 新路由（v2） |
|------------|------------|
| `/log` | `/diary` |
| `/log/new` | `/diary` |
| `/chat` | `/nutritionist` |
| `/products` | `/diary` |
| `/symptoms` | `/diary` |
| `/symptoms/new` | `/diary` |
| `/upload` | `/scan` |

### 日誌頁技術決策：用藥與美容改用 `/api/symptoms`

日誌頁的「用藥與看診」和「洗澡美容」兩個功能，原本預計透過 `/api/usages` 儲存記錄，但 `usages` 資料表的 `productId` 欄位為必填（NOT NULL），無法在沒有綁定產品的情況下建立記錄（例如：純粹記錄「洗澡」這件事而不關聯特定產品）。因此改用 `/api/symptoms`，以 `symptomType: 'medication'` 和 `symptomType: 'grooming'` 作為類型區分，彈性更大、不強制關聯產品。

## API Endpoints

| 路徑 | 方法 | 功能 |
|------|------|------|
| `/api/extract` | POST | 視覺 AI 擷取食品標籤成分 |
| `/api/instant-analyze` | POST | 照片 → 成分安全判讀（safe/caution/danger），存 `InstantAnalysis` |
| `/api/chat` | POST | AI 對話，注入寵物背景資料為 system prompt |
| `/api/analyze` | POST | 相關性分析，存 `AIInsight` |
| `/api/nutrition-ai` | POST | AI 營養摘要（產品堆疊） |
| `/api/recommend` | POST | AI 產品推薦 |
| `/api/tasks` | POST | 生成每週照護任務清單 |
| `/api/analysis` | GET | 規則式成分知識庫分析（不呼叫 AI） |
| `/api/pets` | CRUD | 寵物資料 |
| `/api/symptoms` | CRUD | 症狀記錄（含 grooming / medication type）|
| `/api/pet-products` | CRUD | 寵物產品清單 |
| `/api/reactions` | CRUD | 每日產品反應評分 |
| `/api/health-metrics` | GET/POST | 每日健康指標（BCS/活力/水分）|
| `/api/diary-records` | GET | 依日期查詢該天所有紀錄（症狀+使用+健康指標）|
| `/api/diary-parse` | POST/PUT | AI 解析隨記文字 → 結構化紀錄 → 確認後儲存 |
| `/api/products/web-search` | POST | AI + web_search 搜尋真實寵物食品並做成分分析 |

## 認證方式

**Phase 1（現況）**：Google Login UI 為 mock 實作，點擊按鈕後直接寫入 localStorage，不發出真實 OAuth 請求。

| localStorage key | 值 | 說明 |
|---|---|---|
| `purepaw_user_ack` | `'1'` | 使用者已完成登入（mock） |
| `drpet_userId` | `'local_user'` | 用戶 ID（mock 固定值） |
| `drpet_nickname` | 字串 | 顯示名稱 |
| `purepaw_disclaimer_ack_v1` | `'1'` | 使用者已閱讀並同意免責聲明 |
| `drpet_currentPetId` | 字串 | 目前選取的寵物 ID |

**後續計畫**：串接真實 Google OAuth，`purepaw_user_ack` 改由 token 驗證取代。

## 資料庫架構重點

- `Pet` 為核心實體，幾乎所有模型均以 Pet delete 為級聯刪除對象。
- 陣列型欄位（如 `mainProblems`、`allergies`、`photos`）儲存為 JSON 字串，讀取須用 `parseJson()`（位於 `src/lib/utils.ts`）。
- `PetProduct` 管理寵物的固定／試用產品清單（`listType: "fixed" | "trial"`）。
- `ProductReaction` 記錄每日產品反應評分，唯一約束 `@@unique([petId, productId, date])`。
- `HealthMetric` 記錄每日健康指標（BCS 體態評分 1–9、活力 low/medium/high、水分 low/medium/high），唯一約束 `@@unique([petId, date])`。
- Prisma v7 的 `DATABASE_URL` 不放在 `schema.prisma`，改由 `prisma.config.ts` 設定，runtime 於 `src/lib/prisma.ts` 建立帶 libsql adapter 的 `PrismaClient`。
