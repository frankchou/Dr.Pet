## 使用者身份識別流程

`ClientShell`（`src/components/layout/ClientShell.tsx`）在客戶端 `useEffect` 中執行初始化判斷，流程如下：

```
頁面載入
  └─ ClientShell 掛載（ready = false，不渲染任何內容，避免 SSR hydration 不一致）
       └─ useEffect 執行
            ├─ 讀取 localStorage['purepaw_user_ack']
            │    ├─ 存在 → setIsLoggedIn(true)，接著檢查免責聲明
            │    └─ 不存在 → 顯示 LoginPage
            └─ setReady(true)
```

`ready = false` 期間回傳 `null`，確保 SSR 與 CSR 內容一致，避免 React hydration 警告。

目前為 mock 實作，點擊「使用 Google 繼續」按鈕後：

1. 呼叫 `handleGoogleLogin()`

不發出任何網路請求，不驗證任何 token。後續計畫串接真實 Google OAuth。

## 測試帳號登入機制（DEMO 模式）

**條件啟用**：環境變數 `DEMO_ENABLED=true` 時，NextAuth 加入 `CredentialsProvider`，允許用帳號密碼登入。正式環境不設定此變數，入口完全不顯示。

**前端顯示控制**：`NEXT_PUBLIC_DEMO_ENABLED=true` 時，`ClientShell` 登入頁出現測試帳號表單，否則隱藏。

**登入流程**：

```
使用者輸入帳號（demo@drpet.com）+ 密碼（demo1234）→ 送出
  └─ NextAuth CredentialsProvider 驗證（server-side）
       ├─ 驗證通過 → 建立 session → ClientShell 標記登入完成
       └─ 驗證失敗 → 顯示錯誤訊息
```

**設計原則**：透過環境變數切換，確保測試入口在生產環境完全不存在，不增加安全風險。

## 免責聲明彈窗機制

**觸發條件**：使用者已登入（`purepaw_user_ack = '1'`）但尚未同意免責聲明（`purepaw_disclaimer_ack_v1` 不存在）。

**彈窗行為**：

| 步驟 | 說明 |
|------|------|
| 顯示 | 覆蓋全畫面，`z-[60]`，手機版從底部滑入，桌面版居中彈窗 |
| 滾動偵測 | `onScroll` 事件監聽，距底部 < 16px 時啟用同意按鈕 |
| 短內容例外 | `useEffect` 初始化時若 `scrollHeight - clientHeight < 16`，直接啟用按鈕 |
| 同意 | 點擊按鈕後寫入 `purepaw_disclaimer_ack_v1 = '1'`，關閉彈窗 |
| 後續造訪 | `purepaw_disclaimer_ack_v1` 存在則不再顯示 |

**條款內容**（7 條）：服務性質、非醫療診斷（加粗警語）、資訊正確性、個人化限制、緊急狀況、資料與隱私、同意條款。

**獸醫參考來源聲明**固定顯示於條款末尾，列出 WSAVA、AAFCO、FEDIAF、NRC、農業部等機構。

## 飲食頁機制（`/diet`）

### 日常配餐 Tab

飲食頁主要功能區，結構為：晨食 / 午食 / 晚食三個互斥 Accordion（同時只能展開一個）。

**配餐資料讀取流程**：

```
頁面載入（petId 從 localStorage 取得）
  └─ GET /api/meal-plans?petId=&date=today
       ├─ 有資料 → 回傳 DailyMealPlan（含 MealPlanItem 陣列）
       └─ 無資料 → 回傳空配餐，使用者可新增
```

**食物項目 CRUD 流程**：

- 新增：使用者在 Accordion 內輸入食物名稱 → `POST /api/meal-plans`（若當日計畫不存在則自動建立）→ `POST /api/meal-plans/[id]/items`
- 刪除：點擊項目旁刪除按鈕 → `DELETE /api/meal-plans/[id]/items`

### AI 智能分析配餐流程

```
使用者點擊「AI 智能分析配餐」按鈕
  └─ 前端組裝當日三餐所有 MealPlanItem 資料
       └─ POST /api/diet-analysis（petId + 配餐資料）
            └─ API 呼叫 claude-sonnet-4-6
                 └─ AI 回傳 JSON：
                      ├─ overallScore（綜合評分 0-100）
                      ├─ coreMetrics（蛋白質/脂肪/碳水/纖維四項核心指標）
                      ├─ alerts（警示事項列表）
                      ├─ expertComment（專家點評文字）
                      ├─ replaceRecommendations（建議換掉的食物項目）
                      ├─ storeRecommendations（實體通路推薦商品）
                      └─ detailedReport（9 大項目詳細報告）
```

**前端呈現**：分析結果以 4 個 Tab 顯示（商品換掉建議 / 自拍成分 / 實體通路 / 輸入成分）。點擊「詳細報告」開啟 Modal 顯示 9 大項目完整內容。

## 快訊頁機制（`/news`）

### 三 Tab 動態讀取

快訊頁改版後移除靜態假資料，改由 API 從 `NewsArticle` 資料表動態讀取：

```
頁面載入
  └─ GET /api/news?category=food_safety  ← 食安警報
  └─ GET /api/news?category=danger       ← 危險禁忌
  └─ GET /api/news?category=health       ← 健康知識
```

「健康知識」Tab 的每篇文章若有 `sourceUrl` 欄位，顯示「查看原文」連結（`target="_blank"`）。

### AI 爬蟲機制（`POST /api/news/crawl`）

**授權驗證**：HTTP Header 須帶入 `Authorization: Bearer {CRON_SECRET}`，不符則回傳 401，防止未授權呼叫。

**生成流程**：

```
收到合法請求
  └─ 呼叫 claude-sonnet-4-6
       └─ Prompt：要求以台灣寵物飼主視角，生成三類文章各數篇
            ├─ food_safety：食品安全警報（近期召回/汙染事件風格）
            ├─ danger：危險禁忌（寵物不能吃的食物/物品）
            └─ health：健康知識（營養/日常照護建議）
       └─ AI 回傳 JSON 陣列
            └─ 批次寫入 NewsArticle 資料表（prisma createMany）
```

**Cron 排程**：`vercel.json` 設定 `0 2 * * *`（UTC），即台灣時間每日 10:00 自動觸發。

## 日誌頁機制（`/diary`）

### AI 隨記流程

使用者在日誌頁的「AI 隨記」區塊輸入文字後，按下送出：

1. 前端組裝 `{ petId, messages: [...歷史訊息, 新訊息] }` 送至 `POST /api/chat`
2. `/api/chat` 以 `petId` 從資料庫載入寵物基本資料，注入為 system prompt 上下文
3. 呼叫 `claude-sonnet-4-6` 生成回應
4. 前端將 AI 回應附加至訊息列表並顯示

### 換食計畫 localStorage 持久化

「換食計畫」功能的啟用狀態與開始時間儲存在 localStorage，刷新頁面後不會遺失：

| localStorage key | 值 | 說明 |
|---|---|---|
| `drpet_hasPlan` | `'true'` / 不存在 | 換食計畫是否進行中 |
| `drpet_planStart` | ISO 8601 日期字串 | 換食計畫開始時間（用於計算「第幾天」） |

啟用時呼叫 `GET /api/recommend?petId=...` 取得 AI 推薦食品清單，顯示換食進度天數。停用時同時移除兩個 key。

### 飲食危險詞偵測清單

日誌頁「日常飲食紀錄」的成分 Accordion 展開時，會對每項產品的 `ingredientText` 進行關鍵字掃描，符合以下任一詞即顯示紅色警示標籤：

```
巧克力、葡萄、洋蔥、大蒜、咖啡因、木糖醇、酒精、
xylitol、chocolate、grape、onion、garlic
```

### URL Deep Link 機制

`/diary` 支援 `?section=diet` query 參數。當 URL 帶有此參數時，頁面在掛載後 120ms 自動 `scrollIntoView` 到日常飲食紀錄區塊，讓外部連結（如首頁「快速功能」的飲食記錄捷徑）可以直接跳轉到指定區段。

## 寵物資料讀取機制（userId 過濾）

`GET /api/pets` 改版後依 session userId 過濾，確保各使用者只看到自己的寵物：

```
GET /api/pets
  └─ auth() 取得 session

       └─ 無 session → 回傳全部（向下相容舊裝置）
```

**DEMO 模式影響**：demo 用戶（id: 'demo-user'）只看到 seed 資料中的「布丁」，不會看到其他 Google 用戶的寵物。

## 即時分析三階段 Modal 流程（`/scan`）

掃描分析功能以一個 Modal 覆層完成，`stage` state 控制當前畫面：

```
openModal()
  └─ stage = 'capture'
       ├─ 使用者選擇照片（相機拍攝 / 相簿上傳）
       └─ handleAnalyze() 觸發
            ├─ stage → 'analyzing'（顯示載入動畫）
            ├─ POST /api/instant-analyze（圖片 base64 + petId）
            │    ├─ 成功 → stage → 'result'，顯示判讀結果
            │    └─ 失敗 → stage → 'capture'，顯示錯誤訊息
            └─ result stage：顯示 verdict（safe/caution/danger）、suitabilityScore、成分清單
                 └─ 可選擇「加入試用清單」，呼叫 POST /api/pet-products
```

Modal 開啟期間，`document.body.style.overflow = 'hidden'` 鎖定背景捲動，關閉時恢復。

## AI 營養師 messages 陣列設計（`/nutritionist`）

AI 營養師頁面採用完整訊息陣列傳遞設計，確保 AI 保有對話上下文：

```
send(userInput)
  └─ nextMessages = [...messages, { role: 'user', content: userInput }]
       └─ POST /api/chat
            body: { petId, messages: nextMessages }   ← 傳遞完整歷史
            └─ AI 回應附加至 messages state
```

與單次問答不同，此設計讓 AI 能參考本次對話的所有先前訊息，做出連貫的回應。切換寵物時（`handlePetChange`）會清空 `messages`，重新開始對話。

**建議題動態調整**：建議題清單第三題會根據當前寵物的 `mainProblems` 欄位動態調整，若有設定主要問題（如「皮膚過敏」）則帶入具體建議，否則顯示預設題目。

## 健康指標記錄機制（v1.4.0 新增）

**資料模型**：`HealthMetric`（`@@unique([petId, date])`）

每日記錄三項指標：
- `bodyScore`：BCS 1–9 整數（1=極度消瘦 / 5=理想 / 9=嚴重肥胖）
- `vitality`：`"low" | "medium" | "high"`（低落/正常/活躍）
- `waterIntake`：`"low" | "medium" | "high"`（偏少/正常/偏多）

**寫入路徑**：
1. 日誌頁 `HealthMetricInput` 元件 → POST `/api/health-metrics`（upsert，同日覆蓋）
2. AI 隨記解析 → PUT `/api/diary-parse`（批次儲存，upsert 同日記錄）

**讀取路徑**：
- 首頁 `HealthMetric` 元件：GET `/api/health-metrics?petId=&date=today` → 顯示當日值
- 日曆點選 DayDetail：GET `/api/diary-records?petId=&date=YYYY-MM-DD` → 包含 healthMetric 欄位

## AI 隨記解析機制（v1.4.0 新增）

**流程**：使用者輸入自由文字 → POST `/api/diary-parse` → Claude 解析 → 返回結構化記錄列表 → 使用者確認 → PUT `/api/diary-parse` → 批次儲存

**解析類型**：
- `symptom`：症狀（皮膚/淚腺/腸胃/口腔/耳朵/關節/其他）→ `SymptomEntry`
- `medication`：用藥（疫苗/驅蟲/處方/看診）→ `SymptomEntry(symptomType='medication')`
- `grooming`：美容（居家/基礎/大美容）→ `SymptomEntry(symptomType='grooming')`
- `health_metric`：健康指標 → `HealthMetric`（upsert）
- `food_note`：飲食備注 → `SymptomEntry(symptomType='other')`

## 日常飲食搜尋機制（v1.4.0 新增 AI 搜尋）

**雙軌搜尋**：
1. **本地 DB**（300ms debounce）：搜尋 `Product` 資料表，立即顯示
2. **AI Google 搜尋**（800ms debounce）：POST `/api/products/web-search` → Claude + `web_search_20250305` 工具搜尋網路 → 返回產品資訊 + 成分分析

**AI 搜尋返回資料**：product name/brand/type/description/ingredients + 成分風險計數（toxic/warning/caution/safe）

**加入記錄流程**：點擊 AI 搜尋結果的 `+` → POST `/api/products`（建立產品） → 加入 ProductUsage

## 日曆點選紀錄機制（v1.4.0 新增）

日曆（月曆/週曆）日期有藍點 = 該日有 `SymptomEntry` 或 `ProductUsage`。

點擊日期 → `DayDetail` 面板 → GET `/api/diary-records?petId=&date=YYYY-MM-DD` → 顯示：
- 健康指標（bodyScore/vitality/waterIntake）
- 飲食紀錄（ProductUsage + 品名）
- 其他紀錄（SymptomEntry，依 symptomType 顯示中文標籤）
